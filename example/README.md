# Chi Framework Example

這個資料夾是 Chi Design System 的共用網站框架參考實作，不只是元件圖鑑。

## 目的

- 共用框架統一頁面骨架、導覽、主題切換、內容寬度、響應式規則與通用元件。
- 產品專案只負責自己的頁面內容、資料、路由與業務邏輯。
- 不同產品可以有不同資訊架構；不允許各自重寫一套基礎視覺與通用互動。

## 檔案

- `index.html`: 可直接開啟的框架示範頁。
- `framework.css`: 共用 App Shell 的參考樣式。
- `framework.js`: 主題、手機導覽、設定套用與示範互動。
- `app.config.js`: 產品可自行維護的框架設定範例，包含品牌名稱、標題、版本文字、頁尾與導覽項目。
- 共用 tokens / components / navigation 樣式從上一層載入。

## 目前示範範圍

側邊導覽、頂部工具列、主內容區、頁面標題與操作區、摘要區塊、內容模組、表單、狀態提示、Toast、Light / Dark / System、窄螢幕導覽。

## 設定介面

產品可先複製並調整 `app.config.js`，透過 `window.CHI_APP_CONFIG` 提供：

- `title`: 瀏覽器分頁標題。
- `brand`: 側欄品牌文字。
- `version`: 頂部版本／環境標籤。
- `context`: 頂部目前產品或頁面名稱。
- `footerTitle`、`footerNote`: 頁尾文字。
- `navigation`: 側欄導覽陣列，每項包含 `label`、`href`、`icon`。目前圖示鍵為 `grid`、`file`、`settings`，未知鍵會使用通用文件圖示。

設定只負責框架的可配置資訊；內容區仍由產品自己提供。不要把產品 API、路由守衛、資料存取或身份驗證流程搬進這個共用框架。

## 產品導入原則

1. **目前仍是 Repo 內參考實作**：CSS 以相對路徑載入上一層的設計系統檔案，不能直接把 `example/` 單獨複製到其他 Repo 後就預期能運作。正式導入前，必須先提供可版本化的共用套件或穩定資產，並固定版本。
2. 每個產品只宣告自己的導覽項目、頁面標題、內容模組與功能掛載點。
3. 導覽與內容由產品配置，外觀與行為由框架提供。
4. 不應將整個產品頁面硬塞進同一種版型。資料密集頁、設定頁、導航啟動器與登入頁可以有不同內容佈局，但共用元件和視覺規則一致。
5. 本示範不代表已完成跨 Repo 發布或四個產品遷移。正式導入前，需決定套件發布方式、版本鎖定與更新策略。
